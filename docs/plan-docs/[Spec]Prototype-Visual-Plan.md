## 1. 화면 인벤토리 <!-- T1 -->

### 1.1 화면 3종

**화면은 라우트가 갈리는 단위다.**

| # | 화면 | 경로 | 무엇을 보는가 | 근거 |
| :-: | --- | --- | --- | --- |
| **P1** | 🌳 성장 나무 | `/tree` | 실천 근거가 펼치지 않아도 보이는가 · 5초에 변화가 읽히는가 | AC-1.1 · AC-1.2 · `GRW-003` |
| **P2** | 💳 계획↔실제 대조 | `/review` | 지킴과 넘김이 **화면만으로** 구별되는가 | AC-5.6 · `PLN-004` |
| **P3** | 🌲 월간 숲 | `/forest` | 전월 대비 변화가 60초에 3개 짚히는가 · 획득 별이 스크롤 없이 보이는가 | AC-1.3 · AC-1.4 · `GRW-005` |

**아동 홈은 만들지 않는다** — 아바타 에셋이 D4 미결이다(원장 T10).

### 1.2 상태 6종

**상태는 같은 화면이 통째로 갈리는 단위다.** 한 번에 하나만 성립한다.

| # | 상태 | 쿼리 | 무엇을 확인하는가 | 근거 |
| :-: | --- | --- | --- | --- |
| **F1** | 정상 | `?fixture=normal` | 실천이 쌓였을 때의 기준 화면 | — |
| **F2** | 실천 0건 | `?fixture=empty` | **빈 화면이 결함으로 읽히지 않는가** | ACE-1.1 `앱 결함 인식 ≤ 2/8` |
| **F3** | 정체 14일 | `?fixture=stall` | 원인이 조건 단위로 표시되는가 · 오귀인·불신을 줄이는가 | AC-3.1 · ACE-3.1 · AC-3.2 `각 ≤ 2/8` |
| **F4** | 첫 달 | `?fixture=first` | **델타 0으로 렌더되지 않는가** | ACE-1.2 |
| **F5** | 계획 넘김 | `?fixture=over` | 별이 없는 쪽이 **벌칙으로 읽히지 않는가** | AC-5.4 · P-03 |
| **F6** | 승인 대기 | `?fixture=pending` | 「대기」가 **「미실천」과 구별**되는가 | AC-6.2 · AC-6.3 |

> **7번째 상태를 만들지 않는다.** 필요해 보이면 원장에 토픽으로 올린다.

### 1.3 상태 × 화면 매트릭스

같은 상태라도 화면마다 보이는 것이 다르다. **빈칸을 만들지 않는다** — 모든 칸에 무언가가 있어야 한다.

| | P1 나무 | P2 대조 | P3 숲 |
| :-: | --- | --- | --- |
| **F1** 정상 | 4영역 혼합 + 실천 근거 | 지킴 갈래 ⭐1 | 델타 5항목 + 획득 별 |
| **F2** 실천 0건 | 전 영역 씨앗 + **첫 실천 안내** | **계획 없음 안내** | **수집 중 안내** |
| **F3** 정체 14일 | 「잘 쓰기」 정체 + **원인 조건 단위** | 2주째 기록 없음 안내 | 정체 반영 한 줄 |
| **F4** 첫 달 | 정상과 동일 | 지킴 갈래 | **「다음 달부터 비교할 수 있어요」** |

| **F6** 승인 대기 | **「승인 대기 N건」 배지** | 지킴 갈래 | 승인 대기 델타 |

## 2. 화면 정보 구조 <!-- T2 -->

### 2.1 P1 성장 나무 — 슬롯 5개 · 순서 고정

```
┌──────────────────────────────┐
│ ① 부모 화면 / 성장 나무        │  역할 · 화면명
│   서연 · 3월 · 실시간          │
├──────────────────────────────┤
│ ② 🌳벌기  🌿잘쓰기            │  4영역 2×2 그리드
│   🌱모으기 🌱불리기            │
├──────────────────────────────┤
│ ③ 🛑 정체 원인 (조건부)        │  14일 경과 시에만
├──────────────────────────────┤
│ ④ 승인 대기 N건 (조건부)       │  대기 1건 이상일 때만
├──────────────────────────────┤
│ ⑤ 이번 달 달라진 것            │  실천 근거 — 기본 노출
└──────────────────────────────┘
```

| 슬롯 | 내용 | 없을 때 |
| :-: | --- | --- |
| ① | 역할 · 화면명 · 아이 이름 · 주기 | 항상 있다 |
| ② | **4영역 카드** — 아이콘 · 이름 · 단계 · 진행바 · 조건 요약 | 항상 있다 (F2는 전부 씨앗) |
| ③ | **정체 원인** — 미충족 조건 **전부** · 가장 적게 남은 것 **최상단** | F3에서만 |
| ④ | 승인 대기 건수 | F6에서만 |
| ⑤ | **실천 근거 1~2문장** — **펼치지 않아도 보인다** | F2는 「첫 실천 안내」로 대체 |

**어기기 쉬운 것**

| ❌ | 규칙 |
| --- | --- |
| ⑤를 접어두고 「자세히」로 펼치게 한다 | **기본 노출**이다 (AC-1.2). 접으면 실천이 성장의 뜻으로 읽히지 않는다 |
| ③에 원인을 하나만 쓴다 | **전부** 표시한다. 가장 적게 남은 것이 최상단 (ACE-3.1) |
| 조건부 슬롯 자리에 빈 줄을 남긴다 | ③④는 **조건부**다. 없으면 자리도 없다 |
| 나무 단계를 확정 사양처럼 쓴다 | **D6 미결이다.** 화면 하단에 「예시값」을 표시한다 |

### 2.2 P2 계획↔실제 대조 — 2열 + 회고

```
┌──────────────────────────────┐
│ ① 아이 화면 / 계획 ↔ 실제      │
├───────────────┬──────────────┤
│ ② 적어둔 것    │ 실제로 쓴 것   │  2열 · 업종별
│   🖊 문구 5,000│ 🖊 문구 3,000 │
│               │ 🍬 간식 3,000 │  ← 계획 밖은 강조색
│   합계  5,000 │ 합계  8,000  │
├───────────────┴──────────────┤
│ ③ 회고 문장                    │  갈래별 문구
│ ④ ⭐ 1개 / ⭐ 없음             │  결과 표기
├──────────────────────────────┤
│ ⑤ [확인했어요]                 │  아이가 하는 유일한 조작
└──────────────────────────────┘
```

| 슬롯 | 내용 | 규칙 |
| :-: | --- | --- |
| ② | 계획 · 실제 **2열 대조** | 계획에 없던 업종은 **강조색**. 합계는 굵게 |
| ③ | **회고 문장** | 갈래별로 **다른 문장**. §3.2 전문 사용 |
| ④ | ⭐ 결과 | 지킴 `⭐ 1개를 받았어요` / 넘김 `⭐ 없음 · 가진 별은 그대로예요` |
| ⑤ | 확인 버튼 | **한 번의 조작만.** 작성·선택·감정 입력 없음 |

**어기기 쉬운 것**

| ❌ | 규칙 |
| --- | --- |
| 넘김 갈래에 경고·오류색을 쓴다 | **벌칙이 아니다.** 차분한 강조색(테라코타)을 쓴다 |
| 넘김에서 별을 차감하는 표현을 쓴다 | **차감하지 않는다** (P-03). *"가진 별은 그대로예요"* |
| 넘김에서 회고 문장을 생략한다 | **똑같이 제시한다.** 갈리는 건 별뿐이다 |
| 아이에게 이유를 고르게 한다 | **[확인했어요] 한 번**이 전부다 |

### 2.3 P3 월간 숲 — 슬롯 4개 · 순서 고정

```
┌──────────────────────────────┐
│ ① 이번 달 한 줄                │  요약 문장
│ ② ⭐ 46  이번 달 획득 별       │  스크롤 없이 보여야 한다
│ ③ 지난달과 비교                │  델타 항목
│ ④ (첫 달이면 ③ 자리에 안내)     │
└──────────────────────────────┘
```

| 슬롯 | 규칙 |
| :-: | --- |
| ① | **한 줄 요약.** 상태에 따라 문장이 바뀐다 |
| ② | **획득 별은 스크롤 없이** 보여야 한다 (AC-1.4). 별을 즉시 소진하는 아이의 **유일한 누적 증거**다 |
| ③ | 델타 **항목별 한 줄** — `이전 → 이후` 형식. 증가는 초록 |
| ④ | **첫 달이면 델타를 0으로 그리지 않는다** (ACE-1.2) |

### 2.4 용어 고정

| 쓴다 | 쓰지 않는다 |
| --- | --- |
| **보호자** (문서) / **부모** (화면) | 학부모 · 양육자 |

## 5. 컴포넌트 인벤토리 <!-- T5 -->

**shadcn/ui 자체 구현 금지**(D-08 · REQ-TEC-007). 화면 3종이 실제로 쓰는 것만 설치한다.

| 컴포넌트 | 쓰는 곳 |
| --- | --- |
| `card` | 4영역 카드 · 대조 2열 · 델타 행 |
| `badge` | 단계 · 승인 대기 · 「예시값」 고지 |
| `button` | 확인했어요 |
| `select` | 상태 스위처 |
| `separator` | 슬롯 구분 |
| `progress` | 나무 진행바 |
| `alert` | 빈 상태 · 정체 원인 |

**7종.** 여기 없는 컴포넌트가 필요하면 **원장에 토픽으로 올린다.**
스타일 프리셋은 `base-nova`, 설치는 `npx shadcn@latest init -d -f` 후 개별 `add`.

> **구현 결과** — `badge` · `button` · `select` · `separator` 는 쓰였고,
> `card` · `progress` · `alert` 는 폰 프레임 **밖에서만** 쓸 자리가 남았다.
> 390px 폭에 카드 4장을 넣으려면 기본 패딩을 전부 덮어써야 해서, 프레임 내부는
> 토큰 기반 소형 블록으로 짰다. **설치는 유지한다** — 본 개발의 데스크톱 화면에서 쓴다.

### 6.3 델타 항목 (F1 기준 · 5개)

`사려다 멈춤 2→5회` · `가격 비교 0→4회` · `저축률 12→32%` · `벌기 새싹→나무` · `잘 쓰기 씨앗→새싹`

> **델타는 최소 5개를 렌더한다.** REQ-FUNC-009는 **7개 이상**을 요구하지만, 프로토타입은
> 4영역 중 변화한 것만 표시하므로 상태에 따라 개수가 다르다. **7개 요건은 본 개발에서 충족한다.**

## 7. 확인 도구 <!-- T7 -->

### 7.1 상태 스위처

| 항목 | 값 |
| --- | --- |
| 위치 | **화면 상단 고정 바** |
| 형태 | `select` 드롭다운 6종 |
| 연동 | **URL 쿼리와 동기화** — `?fixture=empty` 로 특정 상태를 링크로 공유 |
| 제거 | 프로토타입 전용. **본 개발 시 이 바만 지우면 끝난다** |

### 7.2 뷰포트

**모바일 폭 390px 고정.** 데스크톱에서는 가운데 정렬하고 폰 프레임으로 감싼다.
실제 사용 맥락과 같고, 인터뷰에서 폰처럼 보여줄 수 있다.

### 7.3 스크린샷

`reports/proto/` 에 상태별로 남긴다. **파일명은 `<화면>-<상태>.png`**.

```
p1-normal.png  p1-empty.png  p1-stall.png  p1-pending.png  p1-first.png
p2-normal.png  p2-over.png   p2-empty.png
p3-normal.png  p3-first.png
```

`p1-first.png` 는 나중에 추가됐다. **첫 달의 나무가 정상과 같아 보이는 문제**가 평가에서 잡혔고,
전용 슬롯(§6.2.1)이 생기면서 그 화면이 증거 대상이 됐다.

화면 3종을 한 장에 담은 **전경 3장**을 함께 남긴다 — 인터뷰에서 상태 전환을 설명할 때 쓴다.

```
overview-normal.png  overview-stall.png  overview-over.png
```

**촬영은 손으로 하지 않는다.** `tools/shoot_proto.sh` 가 13장을 다시 만든다.

```sh
cd app && npm run build && npx next start -p 4312 &
tools/shoot_proto.sh          # 촬영 → tools/trim_shots.py 로 하단 여백 정리
```

한 장에 화면 하나만 담으려면 `?shot=p1` 같은 **촬영 모드** 쿼리를 쓴다. UI가 아니라 통로다.
`next dev` 로는 찍히지 않는다 — HMR 웹소켓이 열려 있으면 헤드리스 크롬이 종료되지 않는다.
